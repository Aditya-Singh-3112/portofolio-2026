Patent

Filed · authoring MLSys submission
Patent · Memory Orchestration

Component-Aware Asynchronous Offloading (CAAO)

Inventor · research manuscript in preparation for MLSys submission

CAAO maps operating-system virtual memory concepts onto deep learning training. It runs a four-stage instruction pipeline — prefetch, compute, offload, update — across independent hardware streams, masking PCIe transfer latency so the GPU is never sitting idle waiting on a copy.

The framework enables enterprise-grade ViT and GAN training on consumer GPUs by integrating zero-copy DMA transfers via pinned CPU memory, eliminating bounce buffers and bounding peak VRAM to the size of the largest active component rather than the whole model.

Master's Thesis

M.Tech, IIIT Allahabad · 2024–2026
Thesis

Implementing Virtual Memory Management in Pipelined CAAO: A High-Throughput, VRAM-Efficient Training Approach

M.Tech Thesis · Information Technology (Machine Learning)

Training a large network on a single GPU has a predictable failure mode: the first few hundred steps look fine, then an allocation fails and the run dies, because a single step needs weights, gradients, optimizer state, and forward-pass activations all resident in VRAM at once. The standard fix — keeping unused weights in host RAM and pulling them back on demand — usually disappoints in practice, because most implementations move data across PCIe as one blocking copy: the GPU finishes a layer, asks for the next, and idles while the bytes cross the bus.

This thesis goes after the waiting, not just the transfer. GPU VRAM plays the role of a small set of physical page frames; host RAM is the swap device behind it. The network is cut into components — each roughly one Transformer block — with only two or three ever resident on the GPU together. Four operations run concurrently on independent CUDA streams: the next component is prefetched CPU→GPU, the current one runs forward and backward, the previous one is shipped back to the CPU, and the optimizer updates weights host-side. Page-locked host memory is what makes it work: once buffers are pinned, the DMA engine moves data without either processor stopping to wait on the other.

Two architectures were evaluated at opposite ends of the memory spectrum. On a small Autoencoder over CIFAR-10, the pinned CAAO variant reached 8,310.63 samples/sec while holding peak VRAM to 422MB, against 554MB for ordinary training. The Vision Transformer is the more honest test: peak memory dropped from 4,910MB to 1,864MB — close to a 62% reduction — but throughput fell from 677 to 361 samples/sec. That tradeoff is reported without dressing it up, because a run that finishes slowly is still worth more than one that crashes on the first batch. In every configuration, the loss curve tracked the baseline without drifting.
